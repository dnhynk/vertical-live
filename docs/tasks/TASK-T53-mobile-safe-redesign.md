# TASK-T53-mobile-safe-redesign

- Task: T53 렌더러 첫 화면을 YouTube 앱 일반 시청 페이지 기준으로 재설계
- Branch: `dnhynk/mobile-safe-redesign` · PR: #<n>
- Spec sections read: §5.2, §5.3, §11, §12.3, §12.4, §14.2(1)
- BOARD decisions/assumptions relied on: D-9, D-22, D-23, D-25, A-15

## Goal

현행 `index.css`의 safe area는 YouTube **Shorts** 화면을 모델링한다 — 오른쪽에 좋아요·공유·댓글
세로 열이 있다고 가정해 `--safe-right: 120px`를 비우고, 아래는 460px만 비운다. 실제 운영 대상은
Shorts가 아니라 **앱 일반 시청 페이지의 세로 라이브**이고(D-23·D-24·HANDOFF의 calibration 정의),
그 화면에는 오른쪽 액션 열이 없는 대신 채팅 오버레이가 훨씬 높이 올라온다. 그 결과 현재
`.screen-bottom`(반영된 행동·성장·다음 선택·CTA 전체)이 YouTube 채팅 오버레이와 입력창 뒤로
들어가고, 스펙 §5.2가 요구하는 4개 항목 중 2개가 시청자에게 도달하지 않는다. T53은 점유 지도를
실제 화면 기준으로 다시 잡고, 그 안에서 4개 슬롯과 CTA가 모두 읽히도록 레이아웃과 시각 언어를
재설계한다.

## 점유 근거 (사용자 제공 실화면, 2026-08-29)

측정 원본: YouTube iOS 앱 일반 시청 페이지, 세로 라이브, 축소 상태. 스크린샷 924×1912.
9:16 영상은 폭에 맞춰지므로 영상 프레임은 화면 y 134–1777(높이 1643)이고, 방송 픽셀 환산 배율은
1920 / 1643 = 1.1686이다. 아래 값은 그 환산 결과(1080×1920 방송 픽셀)다.

| YouTube 요소 | 방송 픽셀 | 성격 |
| --- | --- | --- |
| 헤더(뒤로가기·채널·시청자수·구독·⋮)와 그 스크림 | y 0–195 | 상시 |
| 왕관 뱃지 | x 47–117, y 106–174 | 상시 |
| 선물·이펙트 라벨 열 | x 41–386, y 258–778 | 선물 발생 시 |
| 채팅 메시지 오버레이 | y 1310 이하 | 간헐(메시지 수에 따라 변동) |
| 안내 배너 | y 1678–1789 | 상시 |
| 채팅 입력창 | y 1827–1920 | 상시 |
| 오른쪽 액션 열 | **없음** | Shorts에만 존재 |

따라서 이 화면의 안전 밴드는 **y 195–1310, 폭 전체**다. 현행 상수와의 차이는 세 곳이다.

- `--safe-top: 150px` → 195px (헤더 스크림까지 포함)
- `--safe-bottom: 460px` → 610px (콘텐츠 하단이 1460px에서 1310px로)
- `--safe-right: 120px` → 0px (Shorts 가정 제거)

## Plan

1. `visual/safe-area.ts`를 새로 만들어 위 표의 값과 출처·환산식을 한 곳에 두고, CSS 변수로 내보낸다.
   현행처럼 `:root`에 숫자만 두면 어느 화면을 모델링한 값인지 다음 사람이 알 수 없다. 값은
   `provisional`(A-15 의미)로 표시하고 단위 테스트로 밴드 불변식(상단 < 하단, 밴드 높이 > 0)을 고정한다.
2. `.screen`을 세로 스택에서 **안전 밴드 안의 3구역 배치**로 바꾼다.
   - 오른쪽 세로 레일(x 676–1036): 반영된 행동 · 성장과 장 · 다음 선택. Shorts 가정 제거로
     되찾은 폭을 여기에 쓴다. 왼쪽 상단은 YouTube 선물 라벨 열에 양보한다.
   - 크리처(R3F): 머리 상단이 헤더 스크림(y 195)에 닿지 않도록 프레임 중앙에서 위로 들어올리고,
     오른쪽 레일과 겹치지 않게 왼쪽으로 민다.
   - 하단 플레이트 하나: 현재 욕구 한 줄 → CTA 명령 → 무료 고지. CTA가 실제 채팅 입력창 바로 위에
     오게 해 시선 경로가 `명령 → 입력창`이 되게 한다.
3. 시각 언어 교체. 현행은 동일한 반투명 검정 라운드 카드 5장을 쌓은 대시보드다. 카드 채움을 걷어내고
   타이포 계층과 헤어라인으로 구조를 만든다. 강조색은 화면당 하나(`paletteFor`의 accent)로 제한하고
   CTA 명령어와 진행 바에만 쓴다.
4. 타입 스케일을 축소 생존 기준으로 다시 잡는다. 1080폭 프레임이 폰에서 약 400px로 렌더되므로
   배율은 약 1/2.7이다. 현행 `.slot-label-en`(22px)은 실제 약 8px로 읽히지 않는다. 레일 라벨 26px,
   레일 값 42px, 욕구 값 88px, CTA 명령 52px를 하한으로 둔다.
5. `EffectLayer`·`PaidThanks`가 안전 밴드 밖으로 나가지 않게 중앙 정렬 기준을 밴드 중심으로 옮긴다.

## Assumptions / provisional values

- **A-T53-1 [확인 필요]**: 점유 표는 사용자 단말 스크린샷 1장에서 읽은 값이다. 기종·OS·글꼴 크기
  설정에 따라 헤더 높이와 채팅 오버레이 시작점이 달라질 수 있다. D-25에 따라 실제 public 방송에서
  확인하며, 그때까지 이 값들은 합격선이 아니라 배치 기준이다.
- **A-T53-2 [확인 필요]**: 선물 라벨 열(x 41–386, y 258–778)은 선물이 발생할 때만 나타난다.
  텍스트를 두지 않는 구역으로만 취급하고, 크리처 실루엣의 부분 겹침은 허용한다.

## Result

`visual/safe-area.ts`가 점유 지도와 밴드를 소유하고 `Screen`이 그것을 CSS 커스텀 속성으로 내린다.
`index.css`는 숫자를 다시 적지 않는다. 화면은 세로 스택에서 밴드 안의 3구역 grid로 바뀌었다.

- 오른쪽 세로 레일: 반영된 행동 · 성장과 장 · 다음 선택. 카드 채움 없이 헤어라인과 text-shadow로
  가독을 잡는다. 라벨은 일본어 위, 영어 별칭 아래로 쌓아 400px 폭에서 잘리던 것을 없앴다.
- 크리처: 크라운이 헤더 스크림(y 195)에서 120px 아래에 오도록 들어올리고, 레일 왼쪽 가장자리에서
  40px 떨어지도록 왼쪽으로 민다.
- 하단 플레이트 하나: 현재 욕구(88px) → 무료 명령 3개 → 무료 고지. 다섯 장의 카드를 대체했다.
- 신원 고지: 밴드 아래 `NOTICE_TOP`(1326)~`NOTICE_BOTTOM`(1662)으로 내렸다. 근거는
  `visual/safe-area.ts`의 주석 — §5.2가 5초 안에 읽으라고 하는 네 가지는 전부 밴드 안에 남고,
  standing disclosure는 그 네 가지가 아니며, 밴드가 둘 다 읽을 수 있는 크기로 담기에는 좁다.

### 크리처 배치 실측

world 단위 → 프레임 픽셀 배율을 시야각에서 유도하지 않고 두 지점으로 쟀다. 같은 preview 상태를
group offset `0`과 `(-0.2398, 0.8293)`로 각각 캡처해 크리처가 216행·64열 움직였다 —
**260.5 px/unit**이며, 시야각에서 유도한 250과 4% 다르다. offset 0에서 크라운은 y=413,
오른쪽 가장자리는 x=707이었고, 두 값이 `Scene.tsx`의 배치 상수 근거다. 검증 캡처에서 크라운은
목표 315에 정확히, 오른쪽 가장자리는 638(레일 왼쪽 676에서 38px)로 나왔다.

`docs/tasks/assets/TASK-T53-broadcast-calm-1080x1920.png`,
`docs/tasks/assets/TASK-T53-broadcast-paid-thanks-1080x1920.png`가 결과 프레임이다.
